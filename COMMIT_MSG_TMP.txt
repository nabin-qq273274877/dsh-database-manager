feat(db): 结构页列编辑对齐建表页，并修好列多时操作列看不到

两件事，第二件是报的现象，第一件是对齐要求。

## 结构页列编辑对话框对齐建表页

原来只有 列名 / 类型（扁平列表）/ 类型文本（常驻文本框）/ 可空 / 默认值 / 注释。
现在与建表页同一套：分组类型下拉、长度/值、排序规则、属性、索引、索引名、允许空、
默认值、自增、注释。那个「类型文本」字段去掉了 —— 它对同一个值提供了第二个永远可编辑
的控件，说不清哪个才是权威；自定义类型改为在同一个格子里换出文本框（建表页的做法）。

- 「允许空」默认不勾选，与建表页一致。由此暴露一条 SQLite 边界：往已有数据的表里加
  NOT NULL 且无默认值的列会被它拒绝（实测 Cannot add a NOT NULL column with default
  value NULL）。表单在提交前就说明该填默认值还是勾允许空，而不是把引擎那句话原样抛出。
  MySQL 接受同一条语句（给既有行填隐式默认值），所以不提示。
- 「放在 xx 字段之后」只在新增列时出现。位置是表的结构，不该由「改这一列的类型」顺带
  改动。SQLite 上这个下拉禁用并说明原因：实测它的 ADD COLUMN 把 AFTER x 当作类型名的
  一部分静默接受（列不动，类型变成 TEXT AFTER a）——「静默接受但无效」比报错更糟，所以
  既不发送也不假装可用。
- 属性下发一次，不是两次。服务端把 UNSIGNED/ZEROFILL 存在 COLUMN_TYPE 里（实测
  int unsigned、int(10) unsigned zerofill），所以编辑时要从类型文本里拆出来放进属性
  列表，提交时再合回去。不拆就会同时发出两处 unsigned，得到 INT UNSIGNED UNSIGNED ——
  而 MySQL 接受并归一化它（回读仍是 int unsigned），所以错了也没有任何报错。
- BINARY 属性不预勾选：MySQL 报告它的方式是把列的排序规则改成 _bin（实测
  CHAR(4) BINARY 读回是 char(4) + COLLATION_NAME=utf8mb4_bin），与「显式声明了该排序
  规则」无法区分，猜一个会往本来没有它的列上加。
- 索引选择真的改索引：选主键走「设主键」，唯一/普通走「建索引」，改选择时先删旧再建新
  （MySQL 拒绝一张表有两个主键）。组成联合唯一索引的列不算「这一列唯一」（实测 MySQL 对
  联合唯一索引的首列也报 key='UNI'），否则从那个状态点「唯一」会把两列约束缩成一列。
  「无」与「不变」不产生任何调用 —— SQLite 上改主键是整表重建，空操作会在那里复制整张表。

## 操作列固定在表格最右方，超出时横向滚动

根因：pin 操作列的 CSS 全部限定在 .dbm-data（浏览页的类）下，而结构页的表在 .dbm-table
里，选择器不命中 —— 浏览页有固定列，隔一个 tab 的结构页没有。
实测（12 列长列名，scripts/measure-structure-overflow.mjs）：scrollLeft=0 时操作格的右
边缘在 x=1728.8、视口右边缘 1568，按钮 161px 在可视区外，屏幕上没有任何提示。

还有两处同源缺陷：
- 结构页表头那格没有 dbm-row-actions 类（只有正文格子有），于是「操作」这个表头跟着
  一起滚走 —— 按钮留下了，说明它是哪一列的字没了。实测表头右边缘 1729.3、正下方的格子
  却已正确贴在 1568。
- 左侧多选列同样只限定了 .dbm-data。

现在两类表共用同一套规则。修后实测：三个滚动位置下操作列表头与格子都贴在 1568，
滚到最右时列名格仍可见。

## 其他

- 拆类型的规则抽到 column-spec-form.ts（含「引擎报什么就原样回什么」的往返），
  索引改动计划抽到 column-index-plan.ts；两者都无 React，可直接单测。
- scripts/e2e-sql-editing.mjs 与 e2e-structure-edit.mjs 各改一处：前者原来靠「允许空默认
  勾选」加列，现在改为显式勾选；后者原来往常驻的类型文本框里打字，现在改为从分组下拉里选。
  两处都是被测行为按需求变了，不是放宽断言。
